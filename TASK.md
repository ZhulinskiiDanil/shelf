# TASK: Shelf — быстрый скриншотер, полка и рисование поверх экрана (Windows)

## Цель

Сделать резидентную Windows-утилиту, которая заменяет Lightshot и при этом:
- **не медленнее Lightshot** на пути `PrtScrn → выделить → Ctrl+C`;
- даёт удобные способы отдать снимок куда угодно (путь к файлу, drag-and-drop);
- умеет рисовать поверх экрана во время разговоров и демонстрации экрана;
- работает **полностью офлайн** (никаких сетевых запросов, аккаунтов, облака).

Пользователь будет запускать промежуточные сборки, пока ты работаешь. Поэтому каждая веха должна заканчиваться **рабочим .exe**.

---

## Главный принцип: скорость и тишина

1. Быстрый путь `PrtScrn → выделение → Ctrl+C → Esc/закрытие` — священный. Ни одна новая фича не должна его замедлить или добавить на нём лишний шаг.
2. **Никаких анимаций** в UI захвата: ни fade-in, ни выезжающих панелей. Единственное исключение — затухание «тающих чернил» в режиме рисования (это функция, а не украшение).
3. Ничего не всплывает само после снимка. Никаких тостов, миниатюр, звуков по умолчанию.
4. Процесс постоянно живёт в трее. Окно оверлея захвата создаётся **заранее** и только показывается/скрывается.
5. Кадр экрана захватывается **в момент нажатия хоткея**, до показа любого UI. UI рисуется поверх уже замороженной картинки.
6. Всё, что не нужно для заполнения буфера обмена (запись в историю, генерация миниатюр, OCR и т.п.), выполняется **асинхронно после** закрытия оверлея.

### Целевые метрики (логировать в debug-лог)
- нажатие PrtScrn → оверлей с затемнением виден: **< 50 мс** (цель — быстрее Lightshot);
- Ctrl+C → картинка в буфере и оверлей скрыт: **< 30 мс**;
- потребление в простое: близко к нулю CPU, RAM — разумно (ориентир < 60 МБ без загруженной модели диктовки).

Добавь в лог замеры этих интервалов, чтобы их можно было проверить на каждой вехе.

## Стек

- **Rust** + `windows-rs` (Win32 + WinRT).
- Захват: DXGI Desktop Duplication (fallback — BitBlt).
- Рендеринг оверлеев: Direct2D (+ DirectComposition, если нужно для прозрачности и производительности). Никакого WebView в путях захвата и рисования.
- Окна, которые открываются редко (полка, настройки), можно делать на `egui`/`eframe` или нативно — на твоё усмотрение, главное без заметной задержки открытия.
- Буфер обмена, drag-out файлов (`DoDragDrop` с `CF_HDROP` + картинка), глобальные хоткеи, low-level hooks — через Win32.
- OCR: `Windows.Media.Ocr` (встроен в Windows, офлайн, ru + en).
- Диктовка: `whisper-rs` (whisper.cpp), модель — локальный файл.
- Конфиг: TOML-файл в `%APPDATA%\Shelf\config.toml`, перечитывается при изменении.
- Данные: `%APPDATA%\Shelf\history\` (картинки), простое хранилище метаданных (JSON или SQLite).

Поддержка: Windows 10/11, несколько мониторов, разный DPI на мониторах (per-monitor DPI aware v2).

## Как работать (важно)

- Иди по вехам ниже **по порядку**. Не жди подтверждения пользователя между вехами — двигайся дальше сам.
- В конце каждой вехи:
  1. Собери release-сборку и положи её в `dist/shelf-mN.exe` (N — номер вехи). **Отдельное имя файла на каждую веху**, чтобы запущенная пользователем старая версия не блокировала сборку новой.
  2. Допиши в `CHANGELOG.md` раздел вехи: что сделано и **«Как проверить»** — 3–6 коротких шагов руками.
  3. Сделай git-коммит с понятным сообщением.
- Новая сборка должна корректно работать, даже если старая ещё запущена: single-instance через именованный mutex с понятным поведением (новая версия просит старую завершиться, или пишет в лог, что уже запущена — выбери вариант, удобный для быстрой смены версий; лучше первый).
- **Тесты — минимально.** Юнит-тесты только для чистой логики, где ошибка вероятна и неочевидна (например, пересчёт координат между мониторами с разным DPI, парсинг конфига, генерация имён файлов). UI-тесты не писать.
- Если упёрся в техническое ограничение, выбери разумное решение сам, коротко опиши его в `NOTES.md` и продолжай.
- Не добавляй сетевой код, телеметрию, проверки обновлений.

## Вехи

### M0 — Каркас
- Трей-иконка с меню: «Настройки (открыть config.toml)», «Открыть папку истории», «Выход».
- Single instance, автозапуск (опция в конфиге, по умолчанию выключен).
- Конфиг с дефолтами и hot-reload.
- Регистрация глобальных хоткеев из конфига.
- Логирование в файл (`%APPDATA%\Shelf\logs\`), уровень из конфига.

### M1 — Быстрый захват (замена Lightshot)
- `PrtScrn` (перехватить, чтобы не срабатывал системный обработчик) → мгновенный freeze всех мониторов → затемнение → выделение области мышью.
- Подсветка окна под курсором: клик без перетаскивания выделяет окно целиком.
- Размеры выделения рядом с рамкой, лупа у курсора с пиксельной точностью (можно выключить в конфиге).
- Изменение выделения за края/углы, перемещение, стрелки для сдвига на 1 px (Shift — на 10).
- `Ctrl+C` — копировать в буфер и закрыть.
- `Esc` / правый клик — отмена.
- Корректная работа на нескольких мониторах с разным DPI.
- Замеры времени из раздела метрик в лог.

### M2 — Варианты завершения
Все действия работают прямо из режима выделения, одной комбинацией:
- `Ctrl+C` — картинка в буфер (как в M1).
- `Ctrl+Shift+C` — сохранить PNG в историю и скопировать **путь в двойных кавычках** (`"C:\...\shot.png"`) для вставки в терминал.
- `Ctrl+S` — быстрое сохранение в папку из конфига без диалога.
- `Ctrl+Shift+S` — сохранить с диалогом.
- `Ctrl+D` — закрыть оверлей и «прицепить» файл к курсору: сразу начинается drag-and-drop файла, можно бросить в Discord, браузер, проводник.
- Каждый снимок любым способом тихо попадает в историю (асинхронно).
- Имена файлов: `shelf_YYYY-MM-DD_HH-MM-SS.png` (шаблон в конфиге).

### M3 — Разметка в режиме захвата
- Инструменты: карандаш, линия, стрелка, прямоугольник, эллипс, маркер (полупрозрачный), текст, размытие/пикселизация, нумерованные метки (1, 2, 3… по клику).
- Панель инструментов рядом с выделением, появляется без анимации. Выбор инструментов клавишами (цифры или буквы — задать в конфиге).
- Цвет и толщина: быстрые клавиши + колесо мыши для толщины.
- `Ctrl+Z` / `Ctrl+Y`.
- Все действия из M2 сохраняют результат вместе с разметкой.
- Важно: если пользователь не трогает инструменты, путь M1 не становится медленнее.

### M4 — Полка и история буфера
- Хоткей (по умолчанию `Ctrl+Shift+Space`) открывает полку: сетка последних снимков.
- С полки: перетащить один или несколько файлов наружу (drag-out), скопировать картинку, скопировать путь в кавычках, открыть папку, удалить, закрепить (pin).
- Полка закрывается по Esc, по клику вне её и после успешного drag-out.
- Слежение за буфером обмена: любые **картинки**, скопированные в системе (не только из Shelf), тоже попадают в историю как файлы. Опция в конфиге, по умолчанию включено.
- Лимит истории (количество / размер на диске) в конфиге, закреплённые не удаляются.

### M5 — Рисование поверх экрана (режим разговора)
- Прозрачный click-through оверлей поверх всех окон на всех мониторах. Он должен **попадать в захват экрана** (Discord, OBS при показе всего экрана): не ставить `WDA_EXCLUDEFROMCAPTURE`.
- **Hold-to-draw**: пока зажата клавиша (по умолчанию Caps Lock, подавить её обычное действие; также поддержать боковую кнопку мыши через конфиг), мышь рисует. Отпустил — мышь снова обычная, клики проходят в окна.
- **Тающие чернила**: через N секунд (конфиг, по умолчанию ~2.5 с) после отпускания штрих плавно исчезает.
- С зажатым модификатором (по умолчанию Shift) штрих остаётся до очистки.
- Очистка всего: отдельный хоткей.
- Быстрая смена цвета (клавиши во время рисования). 
- Отдельный хоткей переключения в «залипающий» режим рисования (без удержания) для длинных объяснений.

### M6 — Инструменты для объяснений
- **Лазерная указка**: удержание хоткея — за курсором тянется тающий след.
- **Прожектор**: всё затемняется, кроме круга вокруг курсора; колесо меняет радиус.
- **Лупа** (как ZoomIt): увеличение области вокруг курсора, колесо — масштаб.
- **Нумерованные метки** на экране по клику в режиме рисования.
- **Подсветка кликов**: короткое кольцо в месте клика (включается хоткеем/конфигом).
- **Показ нажатых клавиш**: плашка в углу с последними комбинациями (вкл/выкл).
- Все эти слои тоже должны быть видны в демонстрации экрана.

### M7 — Доска для мыслей
- Хоткей открывает полупрозрачный (непрозрачность в конфиге) холст поверх всего экрана.
- Те же инструменты, что в M3, плюс бесконечное панорамирование (средняя кнопка/пробел+drag) — если сложно, достаточно одного экрана.
- При закрытии доска сохраняется в историю как PNG (если на ней что-то нарисовано) и доступна на полке.

### M8 — OCR
- В режиме выделения: `Ctrl+T` — распознать текст в выделенной области и положить **текст** в буфер.
- На полке: действие «скопировать текст» для снимка.
- `Windows.Media.Ocr`, языки ru + en (использовать установленные в системе; если языкового пакета нет — понятное сообщение в логе и в маленьком уведомлении).

### M9 — Диктовка
- Hold-to-talk хоткей: пока зажат — запись с микрофона по умолчанию, отпустил — расшифровка локально через whisper и **текст в буфер обмена**. Опция в конфиге: сразу вставлять (эмуляция Ctrl+V).
- Модель — локальный файл, путь в конфиге. Если модели нет, в трей-меню пункт с инструкцией, где взять файл и куда положить (сам ничего не скачивай).
- Язык: auto / ru / en в конфиге.
- Модель загружается лениво при первом использовании и выгружается после простоя (настраивается), чтобы не держать память постоянно.
- Ненавязчивый индикатор записи у курсора, без анимаций кроме простого состояния.

### M10 — Запись области
- В режиме выделения: хоткей начинает запись выделенной области в MP4 (Media Foundation) и опционально GIF.
- Рамка вокруг области записи, остановка хоткеем.
- Результат — в историю, с теми же действиями завершения (путь, drag-out).
- Если GIF неразумно сложен — сделать только MP4 и записать в NOTES.md.

### M11 — Настройки и полировка
- Окно настроек (хоткеи, папки, цвета, тайминги, вкл/выкл функций), открывается быстро, без анимаций.
- Проверка конфликтов хоткеев.
- Пройтись по метрикам из раздела «Скорость» и убедиться, что они не ухудшились по сравнению с M1.
- `README.md` с кратким описанием и таблицей всех хоткеев по умолчанию.

### M12 — Умный буфер обмена на виду
Когда в системе что-то копируется (в любой программе, не только в Shelf), рядом с курсором на короткое время появляется небольшой чип: что именно скопировано, с учётом типа содержимого. Чип виден в демонстрации экрана (не ставить `WDA_EXCLUDEFROMCAPTURE`).

Типы и как их показывать:
- цвет (`#RGB`, `#RRGGBB`, `#RRGGBBAA`, `rgb()`/`rgba()`, `hsl()`): образец цвета + значение;
- путь к файлу или папке (в т.ч. в кавычках, и `CF_HDROP` при копировании файлов в проводнике): иконка, имя, размер или число файлов; если путь не существует — показать как текст;
- URL: домен крупно, путь мелко и обрезанно;
- JSON: признак валидности и первые ключи верхнего уровня; при ошибке парсинга — как текст;
- картинка: миниатюра и размеры в пикселях;
- обычный текст: первые ~60 символов в одну-две строки и число символов/строк;
- многострочный код: первые 2–3 строки моноширинным шрифтом.

Требования:
1. Скорость и тишина как во всём Shelf. Чип не влияет на путь `PrtScrn → выделить → Ctrl+C`. Буфер слушать через `AddClipboardFormatListener`, разбор содержимого — вне потока UI захвата. Если буфер занят другой программой — пару раз коротко повторить и тихо сдаться.
2. Появление мгновенное, без анимации. Исчезает через ~1.2 с (настраивается). Короткое затухание при исчезновении — опция, по умолчанию выключено.
3. Окно чипа click-through, без фокуса (`WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW`), поверх всех окон, корректно на нескольких мониторах с разным DPI, не вылезает за край экрана.
4. Быстрые копирования подряд: новый чип заменяет старый, без очереди.
5. Приватность (чип виден в стриме):
   - не показывать содержимое, если в буфере есть форматы `ExcludeClipboardContentFromMonitorProcessing` или `CanIncludeInClipboardHistory = 0` (так помечают менеджеры паролей) — только «🔒 скопировано»;
   - текст, похожий на секрет (длинная строка без пробелов с высокой энтропией, известные префиксы токенов вроде `ghp_`, `sk-`, `xox`, JWT из трёх base64-частей), маскировать: видны первые 4 символа, остальное точками;
   - в конфиге список процессов, при копировании из которых чип не показывается вообще.
6. Ограничить объём разбора: огромный текст или картинку не анализировать целиком, чип строится по первым килобайтам или уменьшенной копии.
7. Хоткей для быстрого вкл/выкл чипа и опция «показывать при копировании из самого Shelf» (по умолчанию да).
8. Новая секция `[clipboard_chip]` в `config.toml` со всеми настройками, с hot-reload, и строки в таблице хоткеев `README.md`.

Тесты только для чистой логики: распознавание типов (цвета, пути, URL, JSON, секреты).

### M13 — История текста и шаблоны
- Использовать уже существующий слушатель буфера обмена (из умного чипа). Каждый скопированный текст сохраняется в историю: время, процесс-источник, сам текст. Дубликаты не плодить: повторное копирование поднимает запись наверх.
- Хоткей (по умолчанию `Ctrl+Shift+V`) открывает компактный список рядом с курсором, как Win+V: сразу можно печатать для фильтрации, стрелки для выбора, Enter кладёт текст в буфер и вставляет в окно, которое было активным до открытия (эмуляция Ctrl+V), Shift+Enter только кладёт в буфер. Открывается мгновенно, без анимаций, Esc закрывает.
- На полке отдельная вкладка «Текст» с тем же списком, поиском, закреплением, удалением, drag-out текста.
- Шаблоны: закреплённые записи могут содержать поля вида `{имя}`. При вставке шаблона появляется маленькая форма для заполнения полей, Enter вставляет готовый текст.
- Приватность: не сохранять текст, если в буфере есть форматы `ExcludeClipboardContentFromMonitorProcessing` или `CanIncludeInClipboardHistory = 0`; не сохранять текст, который детектор секретов из умного чипа считает токеном или ключом; список процессов-исключений в конфиге; хоткей паузы истории. Файл истории шифровать через DPAPI (`CryptProtectData`, область текущего пользователя).
- Лимиты в конфиге: количество записей, срок хранения, максимальный размер одной записи (слишком большие обрезать или пропускать). Закреплённые не удаляются.
- Новая секция `[text_history]` в `config.toml` с hot-reload.

### M14 — Длинный скриншот с прокруткой
- В режиме выделения отдельная клавиша (по умолчанию `Ctrl+L`) запускает захват с прокруткой выделенной области.
- Два режима: автоматический (Shelf сам прокручивает колесом мыши через SendInput в центре области, шаг настраивается) и ручной (пользователь прокручивает сам, Shelf снимает кадры, пока не нажат Enter). По умолчанию автоматический; если окно не реагирует на прокрутку за 2 попытки, переключиться на ручной и показать подсказку.
- Склейка: находить смещение между соседними кадрами сравнением строк в оттенках серого (например, хешами строк или корреляцией полос), а не вслепую по шагу прокрутки. Определять закреплённые шапки и подвалы (строки, одинаковые во всех кадрах сверху и снизу) и не дублировать их в результате: шапка один раз сверху, подвал один раз снизу.
- Остановка: когда два кадра подряд не меняются (конец страницы), по Enter/Esc, или по достижении максимальной высоты из конфига (по умолчанию 30000 px).
- Во время захвата показывать рамку вокруг области и счётчик высоты, рамка и счётчик не должны попадать в кадры (`WDA_EXCLUDEFROMCAPTURE` для них или скрывать на время снимка).
- Результат открывается в обычном режиме разметки (M3) с теми же действиями завершения: Ctrl+C, путь, сохранение, drag-out. Для очень высоких картинок в буфер класть PNG, а превью в оверлее масштабировать.
- Скрывать курсор в кадрах, по возможности возвращать прокрутку окна в исходное положение после захвата (опция).

### M15 — Проверка перед отправкой
- В режиме выделения (и для снимка на полке) клавиша по умолчанию `Ctrl+R`: распознать текст в области через `Windows.Media.Ocr` (с прямоугольниками слов) и найти потенциально личное: email; телефоны (международный формат, а также российские и польские); IPv4 и IPv6; номера карт (проверка Луна); токены и ключи тем же детектором, что в умном чипе; ссылки с секретами в параметрах (`token=`, `key=`, `secret=`, `password=`, `sig=`).
- Найденное подсвечивается рамками поверх снимка, каждую находку можно отключить кликом. Enter применяет скрытие ко всем отмеченным: способ из конфига (сплошная заливка по умолчанию, пикселизация или сильный блюр), с небольшим запасом вокруг слова. После этого работают обычные действия завершения.
- Если ничего не найдено, короткая метка «ничего подозрительного» на секунду, без окон.
- Опционально (по умолчанию выключено, чтобы не нарушать принцип тишины): фоновая проверка после обычного Ctrl+C. Она запускается асинхронно уже после того, как картинка в буфере и оверлей закрыт; если что-то найдено, у курсора появляется тихая метка «⚠ возможно личное, Ctrl+Alt+R чтобы скрыть», и этот хоткей заменяет содержимое буфера скрытой версией.
- Скрытие необратимое: в итоговой картинке пиксели заменены, а не наложены слоем.
- Новая секция `[redaction]` в `config.toml` с hot-reload, детекторы включаются и отключаются по отдельности.

Общее для M13–M15: строки в таблице хоткеев `README.md`, проверка конфликтов хоткеев с уже существующими. Тесты только для чистой логики: детекторы (email, телефоны, карты с проверкой Луна, токены, ссылки с секретами), поиск смещения при склейке на синтетических картинках, шаблоны с полями.

### M16 — Запись под Discord
- Звук в записи: системный звук (WASAPI loopback) и/или микрофон, вторым потоком AAC в том же MP4. Режим в конфиге: `system`, `mic`, `both`, `none` (по умолчанию `system`).
- Лимит размера (по умолчанию 10 МБ, лимит Discord без Nitro; 0 = без лимита): если файл больше, он перекодируется с битрейтом под лимит, при необходимости с уменьшением разрешения.
- Готовое видео сразу кладётся в буфер как файл (`Ctrl+V` в чат прикрепляет его), тихая метка у курсора с размером.
- Экспорт в GIF (без звука, своя палитра): из полки клавишей и опцией формата записи.
- Ничего из этого не работает во время обычного снимка: звук захватывается только между `Ctrl+R` и стопом.

### M17 — Обрезка после записи
- После стопа записи открывается компактное окно-триммер (опция, по умолчанию включена): превью, таймлайн с миниатюрами, ручки начала и конца, воспроизведение, вырезание куска из середины.
- `Enter`/`Ctrl+C` экспортирует результат (с учётом лимита размера M16) и кладёт в буфер, перетаскивание из окна, `Esc` оставляет запись как есть.
- То же окно открывается для видео на полке.

### M18 — Запись с пояснениями
- Рисование на экране (Caps Lock, маркеры, лазер) попадает в видео.
- Подсветка кликов и нажатых клавиш в записи (включается в конфиге, рисуется в кадр).
- Пауза записи хоткеем, индикатор записи/паузы у области, не попадающий в видео.
- Плавный зум к курсору во время записи.

Общее для M16–M18: строки в таблице хоткеев `README.md`, проверка конфликтов хоткеев, путь PrtScrn → Ctrl+C не замедляется. Тесты только для чистой логики: расчёт битрейта и масштаба под лимит, сегменты обрезки, квантование палитры GIF, прямоугольник зума.
