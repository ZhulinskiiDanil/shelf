# Notes — спорные решения

- **Single instance.** Mutex `Local\Shelf.SingleInstance`. Новая копия шлёт старой `WM_APP_QUIT` и ждёт mutex до 5 с. Так запуск свежей `shelf-mN.exe` сразу заменяет старую.
- **Главное окно** — скрытое top-level окно, а не message-only, иначе не приходит широковещательное `TaskbarCreated` (иконка пропала бы после перезапуска Explorer).
- **PrtScrn через `RegisterHotKey`** часто занят (Snipping Tool в Windows 11, Lightshot): `ERROR_HOTKEY_ALREADY_REGISTERED`. В M0 это только предупреждение в логе; с M1 захват идёт через low-level keyboard hook, который подавляет системный обработчик.
- **Hot-reload конфига** — `FindFirstChangeNotificationW` на папке `%APPDATA%\Shelf` в отдельном потоке (без поллинга, CPU в простое ≈ 0), с паузой 150 мс на сохранение редактором. Ошибка парсинга — дефолты + запись в лог.
- **Exe в git не попадают** (`dist/` в `.gitignore`); сборки вех прикладываются к GitHub-релизам `mN`.
- **Захват — BitBlt, а не DXGI Desktop Duplication.** Duplication даёт кадр только при изменении экрана: чтобы мгновенно получать текущий кадр, нужно держать её активной и постоянно забирать кадры (CPU/GPU в простое), а создавать её по нажатию стоит десятки мс. BitBlt всего виртуального экрана в заранее выделенную DIB-секцию стоит ~27 мс на 2560×1440 и идёт **параллельно** с показом окна и захватом фокуса, так что PrtScrn → оверлей ≈ 32 мс. Если на больших конфигурациях метрика выйдет за 50 мс, следующий шаг — DXGI-путь с текстурой прямо на GPU.
- **Оверлей не мигает прошлым снимком.** Пока окно скрыто, оно ещё и DWM-cloaked. Новый кадр рисуется в невидимое окно, и только потом снимается cloak. Анимаций нет.
- **Прогрев при старте:** D2D-устройство, кисти, буфер экрана и первый Present делаются при запуске, а не на первом PrtScrn.
- **Буфер обмена:** CF_DIB кладётся сразу (bottom-up: .NET и старый Office ломаются на отрицательной высоте). PNG — отложенный рендер (`WM_RENDERFORMAT`), кодирование не стоит на пути Ctrl+C.
- **Фокус:** `SetForegroundWindow` из фона запрещён, поэтому используется `AttachThreadInput` к потоку текущего foreground-окна.
- **Хук принимает и инжектированные нажатия** (AutoHotkey, RDP, автотесты).
- **Ctrl+D без зажатой кнопки мыши.** Обычный `DoDragDrop` завершается сразу, если кнопка не нажата. Свой `IDropSource` в режиме «прицепить к курсору» ждёт клика (нажатие + отпускание) и бросает файл. Отмена — Esc или ПКМ. Data object — шелловый (`SHCreateDataObject`: CF_HDROP, IDList и пр.) плюс CF_DIB картинки.
- **История — PNG + `index.json`** (без SQLite: записей немного, JSON читается целиком за миллисекунды). Запись атомарная через `.tmp` + rename. Все записи на диск идут через один фоновый поток, по порядку.
- **Ctrl+Shift+C и Ctrl+D пишут файл синхронно** (после скрытия оверлея): путь должен существовать к моменту вставки или броска. PNG для истории — быстрое сжатие, для «Сохранить как» — сбалансированное.
- **Ctrl+S** кладёт снимок в историю, а копию — в `save.dir`: кодирование PNG одно.
- **Разметка рисуется одним кодом на экране и в файле:** `annot::draw` вызывается для HWND render target и для WIC render target при экспорте. Если разметки нет, экспорт — обычный crop (путь M1 не трогается).
- **Пикселизация** считается на CPU по замороженному кадру (блоки по 6–16 px от размера области) и при экспорте всегда ложится под векторную разметку, независимо от порядка рисования. Для скриншотов это нормально: замазывают текст, а не поверх стрелок.
- **Фигуры хранятся в экранных координатах:** если сдвинуть рамку после рисования, разметка остаётся на месте и может обрезаться (как в Lightshot).
- **Инструменты по одиночным буквам** работают, только когда выделение есть и текст не набирается. При наборе текста все буквы идут в текст, `Ctrl+…` продолжают работать (текст сначала фиксируется).
- **`tools/bench.ps1`** гоняет PrtScrn → выделение → Ctrl+C на нескольких сборках подряд и печатает медианы и максимумы из лога. Так сравниваются вехи с M1.
- **Полка нативная (Win32 + Direct2D), не egui:** окно создаётся при старте и только показывается, как оверлей. Отдельный GUI-фреймворк ради одной сетки не нужен. Миниатюры — сырые BGRA-файлы ≤320×200 (`.thumb`), читаются без декодирования. У старых снимков без миниатюры она создаётся один раз при первом открытии полки.
- **Слежение за буфером:** `AddClipboardFormatListener`. Предпочитается формат `PNG` (браузеры, с альфой), иначе `CF_DIB` (24/32 bpp, BI_RGB/BITFIELDS). Пропускаем, если владелец буфера — Shelf (свои снимки уже в истории) или есть `CF_HDROP` (копирование файлов в Проводнике). Подряд идущие одинаковые картинки отсекаются по хешу.
- **Лимиты** применяются при каждом добавлении: удаляются самые старые незакреплённые, пока не уложимся в количество и размер.
- **Слой чернил:** `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOREDIRECTIONBITMAP` + DirectComposition swap chain с премультиплицированной альфой. Без `WS_EX_LAYERED` окно не прозрачно для кликов других процессов (проверено `WindowFromPoint`). `WDA_EXCLUDEFROMCAPTURE` не ставится. GDI `BitBlt` слой не видит (DComp-контент), зато Desktop Duplication и Windows.Graphics.Capture видят. Поэтому для проверки есть `examples/dda_grab.rs`. Окно скрыто, когда штрихов нет: в простое DWM ничего не композитит.
- **Ввод для рисования:** Caps Lock и цифры перехватывает уже работающий клавиатурный хук. Low-level mouse hook ставится **только на время рисования** (или постоянно, если рисование назначено на боковую кнопку): он затрагивает каждое событие мыши в системе.
- **Задержка штрихов (найдена при ручной проверке):** хук шлёт до ~1000 точек/с, а отрисовка с ожиданием vsync на каждую точку копила очередь — линия «догоняла» руку несколько секунд. Теперь точки только добавляются, перерисовка склеивается в одну на пачку (`request_render`), `Present(0)` без ожидания vsync.
- **Hold-режим рисует без нажатия кнопки мыши** (перо опущено, пока зажат Caps Lock); в «залипающем» режиме рисует ЛКМ, клики не уходят в окна, по краям мониторов цветная рамка-индикатор.
- **Лазер = `Ctrl` + клавиша рисования**, а не отдельный хоткей: удерживать трёхклавишное сочетание неудобно, а Caps Lock уже «ручка». Решение принимается в момент нажатия Caps Lock.
- **Лупа делает стоп-кадр**, как ZoomIt по умолчанию (`Ctrl+1`): живое увеличение через Magnification API на весь экран не попадает в свой же слой и плохо сочетается с рисованием. Стоп-кадр снимается BitBlt (слой чернил в него не попадает: GDI не видит DComp — здесь это и нужно), увеличивается монитор под курсором. Пока лупа включена, ЛКМ глотается, чтобы не кликать вслепую по окнам под картинкой.
- **Показ клавиш скрывает обычный набор:** выводятся только сочетания с Ctrl/Alt/Win и служебные клавиши (Enter, Esc, F1…, стрелки). Иначе во время демонстрации на экран утекли бы пароли.
- **`Ctrl+Alt+…` по умолчанию:** на раскладках с AltGr (польская, немецкая) `AltGr` = `Ctrl+Alt`, так что `Ctrl+Alt+S/Z/C` может перехватить ввод ś/ż/ć. Хоткеи настраиваются в `[ink]`.
- **Тесты ввода:** `SetCursorPos` не порождает событий для low-level mouse hook. Автотесты слоя двигают мышь через `mouse_event` (`tools/` скрипты и `examples/dda_grab.rs` для снимка).
- **Доска — отдельное окно с DirectComposition** (та же связка D3D/DComp, что у чернил, `ink::create_gpu`), но принимает ввод (не layered/transparent). Альфа фона попиксельная: штрихи непрозрачные, фон с заданной прозрачностью (SetLayeredWindowAttributes сделал бы прозрачным всё). Swap chain освобождается при закрытии.
- **Экспорт доски** — векторная перерисовка в WIC (тот же `wic_render`, что у разметки) по рамке всех фигур (`annot::shape_bounds`) с полями 32 px на непрозрачном фоне. Бесконечное панорамирование не мешает: картинка размером с содержимое (не больше 16000 px по стороне).
- **Пикселизация на доске недоступна** (кнопка приглушена): размывать на пустом холсте нечего.
- **OCR ru + en одновременно:** у `Windows.Media.Ocr` один язык на движок, а `TryCreateFromUserProfileLanguages` берёт только первый язык профиля. Поэтому распознаём обоими установленными движками (≈50–100 мс каждый, на рабочем потоке) и выбираем: английский движок читает кириллицу как латинские двойники («колесо» → «Koneco»), а кириллицу выдаёт только русский. Если в русском результате ≥ 50% букв кириллические — берём его, иначе английский.
- **Уведомления:** единственное исключение из «ничего не всплывает» — ответ на явное действие, которое не дало результата (OCR без языкового пакета или без текста). Это беззвучный balloon трея.
- **Фоновая работа → UI:** `run_on_main` передаёт замыкание в UI-поток через `PostMessage` (буфер обмена и окна живут там).
- **Сборка whisper.cpp (`.cargo/config.toml`):** крейт `cmake` подставляет в `CMAKE_*_FLAGS_RELEASE` флаги `cc` без `/O2`, и под MSVC whisper.cpp собирался без оптимизаций (в 10 раз медленнее). Release-флаги заданы явно; ggml собирается под AVX2/FMA/F16C, а не `GGML_NATIVE` (иначе exe падал бы на CPU старше машины сборки). OpenMP выключен: тянет `vcomp140.dll`, а прирост был в пределах шума.
- **Статический CRT** (`+crt-static`, `/MT` для whisper.cpp): exe один и портативный, без MSVCP140/VCRUNTIME140.
- **Сборка требует CMake и libclang** (bindgen из whisper-rs-sys): `LIBCLANG_PATH` на папку LLVM `bin`.
- **Клавиша диктовки — через low-level хук** (нужно отпускание, `RegisterHotKey` его не даёт). У сочетаний с Alt/Win после проглоченной клавиши шлётся «маскирующая» клавиша `0xE8`, иначе одиночное отпускание Alt открыло бы меню окна (как в AutoHotkey).
- **Микрофон — WASAPI shared mode** в формате микшера (обычно float 48 кГц стерео) → моно → 16 кГц линейной интерполяцией (для речи достаточно). Шумовые маркеры whisper (`[музыка]`, `(смех)`) вырезаются.
- **Память в простое:** ~80 МБ рабочего набора давали заранее созданные оверлей, D2D-устройство и буфер экрана (ради < 50 мс на PrtScrn). После прогрева вызывается `EmptyWorkingSet`: в Диспетчере задач ~3 МБ, страницы возвращаются мягкими page fault при следующем захвате (A/B с M1 — в пределах шума). Private bytes (~160 МБ) — в основном резервы графического драйвера под D3D, физическую память они не занимают.
- **Модель для проверки** (`ggml-tiny.bin`) скачивалась вручную только для теста разработчиком; в репозитории и в программе её нет. `examples/transcribe.rs` гоняет модель по WAV-файлу.
